# DevTools

zenit ships two complementary dev tools (`ui.devtools`):

1. **Panel** — a full DevTools in its own window (four views — Elements /
   Components / Console / Performance — plus Layout/Style/State/Events/Render/Trace
   detail pages):

   ```zig
   // inside the mount of a second native window:
   return ui.devtools.mountPanel(cx, target_cx, .{ .title = "My DevTools" });
   ```

   Complete runnable example: `examples/devtools_probe` (target window + DevTools
   window):

   ```bash
   zig build devtools-probe
   open "zig-out/DevTools Probe.app"
   ```

2. **Overlay** — a hover inspector inside the app window (dashed outline + a
   size/component-name label):

   ```zig
   try ui.devtools.overlay.attach(cx, scope, root, .{});
   ```

## Console panel

The Console panel reads the observed window `target_cx`'s own bounded log
repository. Applications write through `cx.console()`; capture starts before
DevTools is opened, and once the panel opens, history still within capacity is
backfilled:

```zig
const log = cx.console();
log.info("application ready", .{});
log.scoped("network").warn("request retry {d}", .{attempt});
log.writeAt(.err, @src(), "save failed: {s}", .{@errorName(err)});
```

The panel provides:

- a 100%-width toolbar with a stretchable text filter box;
- combined Debug / Log / Info / Warn / Error filtering;
- Clear (clears the target's authoritative Console repository, not just the
  current view);
- level color dots, scope tags, group indentation, and source locations;
- a bounded virtual list that auto-follows new logs "only while the user is at
  the bottom";
- `shown / captured / evicted / dropped` integrity status.

Filtering runs locally inside DevTools and does not mutate the target
repository. The Console page polls an atomic revision every 50ms and pulls an
incremental snapshot only after content changed; logs never dirty the target,
nor pollute the target's Performance metrics.

For the full API, configuration, Release defaults, the E2E harness, and
troubleshooting, see [Console and the DevTools Console](CONSOLE.md).

## Performance panel semantics

- **Refresh model**: DevTools is a passive observer, driven by its own
  keep-alive polling (10Hz on the Performance page, 4Hz on the others). It does
  not — and does not need to — redraw at the target's frame rate; the charts
  read the cross-frame history ring on the target Cx.
- **FPS semantics (rolling window)**: the monitor continuously samples deltas
  of `target.frame_count` into 100ms wall-clock buckets — `FPS:` shows a
  rolling mean over the last ~1s and naturally drops to 0 when the target stops
  producing frames. This is Chrome-FPS-meter semantics: the chart always rolls
  forward; it never freezes a snapshot of "the last N rendered frames" on
  screen.
- **idle annotation**: when the target produces no frame for more than ~0.7s,
  the FPS row shows `FPS: 0 — idle (not rendering)` and switches to a secondary
  color. This is the normal state of power-saving frame stops, not a stall; it
  is also what lets the panel tell "a steady 60fps" apart from "not rendering
  at all".
- **Bar chart**: a scrolling chart of 64 100ms buckets (a ≈6.4s window).
  Buckets with frames draw the bucket's average frame time (green ≤ 1.1× the
  refresh period < yellow ≤ 1.5× < red); buckets without frames are a 2px
  neutral baseline — an idle period shows up as the chart rolling out a flat
  line, not freezing. The baseline is the current display refresh period
  (`display_refresh_hz` is polled every frame, so it keeps up when you drag
  across mixed ProMotion/60Hz displays).
- **Cx-side frame-interval history** (`frame_interval_history_us`): samples
  only real rendered frames, clamps to ≥ the refresh period, and drops
  >500ms idle-resume intervals — consumed by P95-style statistics; the panel
  chart no longer plots it directly.
- **Timing row**: the target's layout / render command-generation times (CPU
  wall clock, backfilled every frame by the `zenit_app` renderer). For finer
  cross-frame statistics (GPU execution, P95), see
  `renderer.last_frame_stats` / `renderer.timing_ring`.

## goto-source

Hovering a row in the Elements tree reveals a `↗`; clicking it opens the
component definition in an external editor. Apps must configure source roots at
startup (build artifacts do not know where the sources live):

```zig
ui.devtools.source_link.configure(.{
    .framework_root = "/path/to/zenit",
    .app = .{ .entries = &my_generated_index.entries, .root = "/path/to/app" },
    // .editor defaults to `code --goto {file}:{line}:{col}`
});
```

The app index is generated by the same AST scan as
`tools/gen_component_index.zig` and **must be sorted by name** (configure
asserts in Debug builds).

The Layout / Style detail pages also show a `↗` after attribute values that
have a reliable source:

- `boxStyled` / `hstackStyled` / `vstackStyled` / `textStyled` point to the
  definition of the named style function;
- plain `box` / `hstack` / `vstack` / `text` point to the call site of the
  inline style;
- `setStyle` records the last writer per field and takes precedence over
  builder provenance.

Attribute provenance uses symbol information in the Debug executable and is
resolved only on click, off the render hot path; Release builds with debug info
stripped show no button. Writing `node.style.foo = ...` directly cannot be
intercepted, so it does not update the last writer; runtime mutations that need
precise tracking should go through `setStyle`.

## Smoke test

`bash scripts/run_devtools_smoke.sh` opens a real window and runs two-phase
assertions (active phase: FPS backfill + DevTools keep-alive; stopped-frame
phase: keep-alive survives + idle annotation). Use it for CI / pre-release
regression.

## Notes

- `ui.perf_overlay` is a standalone counter for hosts that bring their own
  render loop (bypassing the `zenit_app` runtime); the framework does **not**
  feed it data. It is a process-level singleton — multi-window hosts should
  keep their own state or read the Cx-side facilities directly.
- While a DevTools window is open, it is a persistent low-frequency wakeup
  source (10Hz/4Hz self-polling); that is a deliberate trade-off for live
  monitoring, and it affects only the DevTools window itself.

## Debug environment variables

The framework ships a set of `ZENIT_*` switches for bisecting
rendering/interaction problems without changing code. They are **not public
API**: no cross-version stability is guaranteed, and they should not be written
into application logic; they are ad-hoc gates for troubleshooting. Unless
stated otherwise, setting any non-empty value enables them (usually `1`).

This section is only an index, answering "which switches exist and roughly
what each covers"; it does not cover troubleshooting methodology.

### Rendering pipeline

| Variable | Effect |
|---|---|
| `ZENIT_DEBUG_CMDSTREAM` | Print command-stream signatures per frame; pin down whether "draws wrong / doesn't draw" happens at record or replay time |
| `ZENIT_DEBUG_DLIST` | Dump display-list contents |
| `ZENIT_DEBUG_SURFDUMP` | Dump surfaces layer by layer — the primary tool for overlay/compositing issues |
| `ZENIT_DEBUG_LAYER` | Layer-tree structure logging |
| `ZENIT_DEBUG_PREPASS` / `ZENIT_DEBUG_PASSCOUNT` | Pre-pass trip count and pass count |
| `ZENIT_DEBUG_TEXCREATE` | Texture-creation logging (chasing texture leaks / duplicate creation) |
| `ZENIT_DEBUG_SHADOW` | Shadow drawing path |
| `ZENIT_RENDER_DIRTY_DEBUG` | Dirty-region marking source (note: historically rate-limited; readings are sampled snapshots) |
| `ZENIT_SNAPSHOT_DEBUG` | Snapshot capture path |
| `ZENIT_DEBUG_OVERLAY` | Overlay structure and lifecycle (process-level cache, fixed after first read) |

### Disabling optimizations (for bisection)

Turn an optimization path off and see whether the problem disappears, to decide
whether that optimization introduced it.

| Variable | What it disables |
|---|---|
| `ZENIT_NO_RETAINED` | Retained compositing; everything goes through full repaint |
| `ZENIT_DISABLE_PARTIAL_REPAINT` | Partial repaint |
| `ZENIT_DISABLE_SUBTREE_SPLICE` | Display-payload reuse for clean subtrees |
| `ZENIT_DISABLE_SUBTREE_PAYLOAD_REPLAY` | Subtree payload replay |
| `ZENIT_DISABLE_SPANNED_TEXT_RETAINED` | The retained path for rich text |
| `ZENIT_DISABLE_SCROLL_CLIP` | Scroll clipping tokens |
| `ZENIT_NO_BLUR` / `ZENIT_NO_BLUR_HYSTERESIS` | Background blur / its hysteresis |
| `ZENIT_FULL_RUNTIME_REBUILD` | Force a full rebuild of the runtime index every frame |

### Liquid Glass

`ZENIT_DEBUG_GLASS`, `ZENIT_DEBUG_GLASSCAP`, `ZENIT_DEBUG_GLASSHOVER`,
`ZENIT_DEBUG_GLASS_RT`, `ZENIT_GLASS_NOPAD`.

> When changing glass-related code, note: **e2e pixel assertions cannot catch
> problems like "the wrong shader was used"** — you must eyeball the
> screenshots.

### Hit testing / interaction

| Variable | Effect |
|---|---|
| `ZENIT_HIT_SCENE_DEBUG` | Hit-scene construction |
| `ZENIT_DEVTOOLS_HIT_DEBUG` | DevTools pick hit testing |
| `ZENIT_DEBUG_MOUSEEV` / `ZENIT_INPUT_DEBUG` | Mouse / input event streams |
| `ZENIT_DEBUG_OUTSIDE_CLICK` | Outside-click determination (when popovers/menus close) |
| `ZENIT_DEBUG_DRAG` / `ZENIT_DRP_PREVIEW_TRACE` | Drag-and-drop and the drag preview |
| `ZENIT_SCROLL_DEBUG` (pair with `ZENIT_SCROLL_DEBUG_MIN_INTERVAL_MS` to rate-limit) | Scrolling |
| `ZENIT_POPOVER_DEBUG` / `ZENIT_DEBUG_MENU` | Popovers and menus |
| `ZENIT_CURSOR_DEBUG` | Cursor shape |

### Text / IME

`ZENIT_TEXT_FLICKER_TRACE`, `ZENIT_TEXT_BRACKET_DEBUG`, `ZENIT_TEXT_BRACKET_NODE`,
`ZENIT_TEXT_OFFSET_INVALID`, `ZENIT_MD_FLICKER_DEBUG` (Markdown redraw flicker),
`ZENIT_IME_NO_REPLACEMENT`,
`ZENIT_MAX_IME_PREEDIT_QUEUE` (numeric; preedit queue cap).

### Frame pacing / performance

| Variable | Effect |
|---|---|
| `ZENIT_FRAME_PACING` | `display_link` (default) or `poll`; the rollback lever when CVDisplayLink is suspect |
| `ZENIT_DEBUG_FRAMEPACE` | Frame-pacing logging |
| `ZENIT_DEBUG_JANK` | Jank attribution |
| `ZENIT_DEBUG_WANTS_FRAME` | Who is requesting the next frame (for "idle never stops frames") |
| `ZENIT_HOOK_TRACE` | Hook execution trace |
| `ZENIT_MOUSE_MOVE_SOFT_LIMIT` | Soft cap on mouse-move events (numeric) |

### Self-checks / audits

`ZENIT_LAYOUT_INTEGRITY` (layout invariant self-check),
`ZENIT_SELF_SCOPE_AUDIT_EVERY_FRAME` (runs the self-scope audit every frame
instead of the default down-sampled cadence),
`ZENIT_DISABLE_HOOK_SELF_SCOPE`, `ZENIT_ROUNDED_CLIP_LAYER`,
`ZENIT_ENABLE_EFFECT_CLIP_BRIDGE`.

### Test-infrastructure only

`ZENIT_E2E_FILE_RPC_DIR` (see `docs/HARNESS.md`),
`ZENIT_A11Y_ANY_WINDOW` / `ZENIT_A11Y_DEAD_WINDOW` / `ZENIT_A11Y_INVALID_HANDLE`,
the `ZENIT_*_NO_MAIN` family (`DRAG_EVENTS` / `GLOBAL_EVENTS` / `MENU_ACTIONS` / `TEXT_EVENTS`,
letting native tests skip main-thread assertions), `ZENIT_RUN_AUDIT_VIOLATION_PROBE`.
